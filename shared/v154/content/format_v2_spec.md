## 1. 画面構成：1シーン1画像

- 1シーン＝画像1枚。パネル分割（2分割・3分割、PA/PB等の複数画像コラージュ）は使わない。
- 画面設計の段階でも分割は設計しない。比較・列挙をしたい場面でも、単一の画像で表現できる設計にする。
- 画面密度の目安：約20分の動画で80〜90画面（平均約15秒／画面）。同じ被写体の連続画面は統合する。

## 2. 画像の動き（motion）

各シーンに motion を1つ割り当て、シーン尺いっぱいに「ゆっくり」動かす（Ken Burns 系）。
**動きの量は倍率1.20を標準とする**（2026-11-12、デモ比較を経て本人が 1.20 を既定に決定。最終版を本人が視聴し、この量で問題ないことを確認済み）。

| motion | 内容 | 用途 |
|---|---|---|
| zoom_in | 1.00 → 1.20 で寄る（既定） | 標準 |
| zoom_out | 1.20 → 1.00 で引く | スケール感を見せる場面（巨大生物・広がり・全体像） |
| pan_right | 倍率1.20で固定し、画面の端から端までゆっくり流す（移動量は画面幅の約16.7%） | 横に広い被写体、流れ・移動の含意 |
| pan_left | 倍率1.20で固定し、画面の端から端までゆっくり流す（同上） | 同上 |
| pan_up / pan_down | 倍率1.20で固定し、画面の端から端までゆっくり流す（移動量は画面高の約16.7%） | 縦の広がり・落下・上昇の含意 |
| static | 固定。図版は固定か、ごく緩いズーム（1.04まで） | 図版・文字を読む画面（可読性優先） |

ルール：
- **パンを含む全ての motion は倍率1.20を基準に実施する。** V153 の初回適用ではパンが倍率1.06・移動量約6%で実装され、視聴上「動きが付いていない」状態だったため、2026-11-12 の本人の指摘で明確化した。微小なパンは不可。
- motion は画面設計（board）にシーンごとに記録する。割り当て漏れは不可。
- 同じ motion を3シーン連続させない（単調さ回避）。
- 動きは画像だけに適用する。字幕帯と字幕は動かさない（§4）。
- チャッピーが画面設計を作る場合もこの表から割り当て、Muse が最終チェックする。

## 3. 章タイトルカード

プロローグ／第○章／エピローグの章名は、カードでのみ見せる。

- **読み上げない**（ナレーション対象外）。尺は約4秒。
- おしゃれな背景画面の上に、文字が1文字ずつタイピング表示される演出。速度は約8〜10文字／秒、打ち終わりにカーソル（▌）の点滅＋約1秒の静止。
- **タイピング音あり**：1文字ごとに打鍵音を鳴らす。音源はリポジトリ格納済みのものを使い回す（V153：shared/v153/format_v2/audio/type_key.wav、48kHz・16bit・モノラル・約0.078秒、制作側のオリジナル生成）。
- 背景：考える夜の月のキャラクター（チャンネルアイコンの、本を読む三日月キャラ）を使う。全章でトーンを統一する。
  - 参照画像：`~/workspace/kangaeru-yoru/moon_character_reference.jpg`（チャンネルページのスクショから切り出したもの。原画ファイルは存在しない）
  - 背景の生成とタイピング演出の「見せ方」の設計はチャッピー（ChatGPT）が担当する。
- デザイン言語：既存の「黒×金・静かな高級感」に合わせる。

### タイトル行の除外（必須・V153の不具合教訓）

- 台本（board）では、章タイトル行が各章の最初のシーンの本文冒頭に埋め込まれていることがある。
- **音声合成の入力と字幕生成の両方から、タイトル行を明示的に除外すること。**
- QA では「各章の最初の字幕が本文から始まっていること」を必ず確認する。

## 4. 字幕

- 画面最下部に、横幅100%・不透明な黒い帯を敷き、その上に字幕を置く。画像へ直接文字を重ねる方式は使わない。
- 帯の高さ：1080p で約130px（画面高の約12%）に固定。
- 字幕文字：白・中央揃えで帯の中央に配置。
- 帯と字幕は固定レイヤーとし、画像の motion の影響を受けない。
- 画面設計の前提：被写体の重要部分を画面下部（帯と重なる領域）に置かない。

## 5. 音声

- ナレーション：VOICEVOX 青山龍星（クレジット表記「VOICEVOX:青山龍星」）。
- **読み上げ注意（2026-11-12 本人指摘）**：青山龍星は「少し」を「しょうし」と読む（V153 の閉めの文で発生、本人の判断で V153 はそのまま公開し次回以降で修正）。次回以降、台本の「少し」は「すこし」とかな表記にする等、読みが「すこし」になるよう台本側で対処する。QA では定型の閉め文など重要フレーズの読みも確認対象とする。
- 語り手の口調は常体（だ・である調）。ですます調は使わない。
- 台本の本文は承認済みの文面を1文字も変えない。

## 6. 出力形式

- 1920×1080、30fps、H.264／AAC の MP4。
- 納品は GitHub Release に公開し、Muse がダウンロードして実物検証してから本人へ渡す。

## 7. 素材の権利ルール

- 使用可：Public Domain／CC0／出典ページ等で再利用可と確認でき、出典・作者・ライセンスを記載できる画像（CC BY 等）。
- 使用不可：再利用可否が確認できないもの、転載不可、All rights reserved、**CC BY-SA**、NC／ND、条件が使い方と合わないもの。
- クレジット（出典・作者・ライセンス）は素材監査と完成報告に必ず記録する。
- 使用できる収集画像がない不足分のみ生成で補ってよい（生成理由を記録する）。
- 権利だけでなく、被写体・構図・用途への適合と解像度を全画面分フルサイズで確認してから確定する（サムネイルだけで判定しない）。

## 10. 運用ルール（V153 の教訓）

- **定常運用フロー（2026-11-12 本人決定）**：本人が台本を渡したら、Muse が新規の制作チャットを立ち上げて台本と本仕様書をチャッピーに渡し、チャッピーが画面割り（シーン割り・画像指示・motion 割り当て・章カード）を作成して、そのまま GitHub Actions で動画制作まで進める。素材は §7 の権利ルールを適用し、全画面が権利＋適合を通るまでは動画工程に入らない。完成品は Muse が §9 で検証してから本人へ納品する。**納品前に BGM 工程を必ず通す**：Muse が章ごとに選曲・取得し（章構成が固まった段階で制作と並行して準備してよい）、完成 MP4 の検証後にローカルで BGM ミックスを行い（実装方式と確定値は「BGM」節、ツールは ~/workspace/kangaeru-yoru/bgm_tool/bgm_mix.py に章境界と曲の対応表 TSV を渡す）、映像ストリームの一致とラウドネスを再検証したうえで、BGM 版を最終納品物とする。本人から送る必要があるものが出た場合のみ、Muse がその時点で知らせる。

- 制作側の報告だけで「完了」としない。納品判定は Muse の実物検証（§9）に基づいて行う。

## BGM（2026-11-12 本人が方針決定）

- **章単位で選曲する**：動画全体で1曲ではなく、章ごとにその章の内容・雰囲気に合う曲を当てる。
- **音源は DOVA-SYNDROME**：章に合う曲を DOVA-SYNDROME から取得して使う。選曲・取得・各曲の利用条件確認・クレジット記録は、画像素材と同様に Muse が素材収集の一環として担当する。
- **クレジット**：使用曲は動画の概要欄に DOVA-SYNDROME の表記ルールに従って記載する。クレジット情報は素材監査と完成報告にも残す。
- **適用範囲**：初回実装は V153 最終版 v5 に対して行った（本人の指示で次回作ではなく現行最終版に適用）。以降の動画も完成後に同じ方式で BGM を付ける。
- **実装方式（確定）**：DOVA-SYNDROME のライセンスは音源ファイル自体の配布・再公開を禁止するため、生の MP3 を公開リポジトリへコミットしたり Release に含めたりしない。BGM ミックスは、完成した MP4 に対する後処理として Muse がローカルで実施する（映像ストリームはバイト単位でコピーし、音声だけを再構築する）。制作側（ChatGPT／GitHub Actions）では実装しない。
- **ミックス確定値（V153 初回実装で確定）**：各章の曲は章の尺に合わせてループ（継ぎ目は1.5秒クロスフェード）またはフェードアウトし、章ごとに統合ラウドネス −28 LUFS にそろえる。ナレーションをサイドチェインにしたダッキング（threshold 0.02／ratio 6／attack 20ms／release 450ms）をかけ、ナレーション下ではベッドが実測 +0.5dB 未満の寄与に収まることを確認。章の切り替わりは前曲フェードアウト2秒・次曲フェードイン1.5秒（冒頭フェードイン2秒、終端フェードアウト3秒）。最終段で全体を −14 LUFS 目安にラウドネス調整し、トゥルーピークは −1 dBTP 以下（エンコード後の実測で担保するため loudnorm の TP 目標は −2 に置く）。
