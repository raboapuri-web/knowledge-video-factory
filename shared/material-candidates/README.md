# 素材マスター連携（制作時の候補追加）

対象はユーザーのGoogleスプレッドシート「素材マスター」本体。共有リポジトリにスプレッドシートIDや認証鍵を書かないこと。

## 動画制作担当者の必須工程

1. 既存マスターの「分類・素材候補・使えそうなテーマ・場面・登録」を照合する。背景、パーツ、人物をそれぞれ比較し、表記だけが異なる既存素材を新規候補にしない。
2. 台本に沿った映像・シーン分割の**開始時**に、繰り返し使える新しい素材を提案する。使い捨ての一瞬のカメラ構図やサーバー上だけのコードオブジェクトは候補にしない。
3. shared/material-candidates/vNN.json を新規作成する。category は「背景」「パーツ」「人物」のみ、name は再利用できる素材名、use_case は具体的な使用テーマ・場面。動画ごとにファイルを増やし、過去の manifest は上書きしない。
4. 登録（D列）は編集しない。素材を実際に画像化・採用した事実が確認できない限り、空欄のまま候補だけを追加する。
5. GitHub Actions「Sync Material Master」はこの manifest の作成・編集で起動し、Google Sheetsの既存B列と照合して未登録名だけをA:C列へ追記する。再実行時も重複追加しない。元データの修正、削除、勝手な登録済み変更はしない。

## 無人でGoogle Sheetsへ反映するための一度だけの認証設定

GitHub ActionsがユーザーのGoogle Driveアカウントのプラグイン権限を自動的に流用することはできない。無人更新を利用する場合は、利用者自身でGoogle CloudにSheets APIが使える専用サービスアカウントを用意し、対象スプレッドシート**のみ**をそのサービスアカウントのメールへ編集者として共有する。

その後、GitHubリポジトリの Settings → Secrets and variables → Actions へ、以下の2つのSecretを追加する。認証情報をリポジトリのファイル、PR、Issue、チャット、スクリーンショットに貼らないこと。

- `MATERIAL_MASTER_SHEET_ID`: 元のGoogleスプレッドシートID。
- `MATERIAL_MASTER_SERVICE_ACCOUNT_JSON`: 対象シートの編集権限を与えたサービスアカウントのJSON鍵全文。

両方のSecretがない場合、同期ワークフローはGitHub上の候補一覧を残して安全にスキップする。**同期成功と取り違えないこと。** サービスアカウントが設定されたら、Actions → Sync Material Master → Run workflowで既存manifestを遡って反映できる。既存名はスキップされる。

ChatGPT内で制作する場合は、接続済みGoogle Drive経由で元のシートの最新行を照合・追記することも可能。これはその会話で明示的に実行した場合のみ反映され、GitHub Actions単独での無人同期とは別の経路である。
